# Review Project Candidate

Read [the shared operating policy](../../references/operating-policy.md) completely before acting.

## Review

1. Reread the originating same-named Area home and locate the human-authored Proposed Projects entry. If the entry is absent, do not reconstruct it from notes or history.
2. Load its linked `xPM/Notes/PC-*` file when present. Treat that note as derived shaping support, never as activation or authority over the Area home.
3. Clarify the desired outcome, finish line, boundaries, dependencies, likely profile, evidence of value, capacity cost, and conditions that would justify starting now.
4. Distinguish `captured`, `candidate`, and `ready` as optional maturity interpretations. `ready` still means inactive.
5. Recommend one of: leave captured, shape further, mark ready for an explicit promotion decision, decline, or promote now subject to explicit user approval.
6. If promotion is approved, hand off to the applicable project-creation workflow with origin preserved. Do not create, move, or delete records through this review skill.

A review request is read-only. Update the Area entry or PC note only when the user asks to capture the accepted shaping result.

## Deliver

Lead with the recommendation, then give the candidate's proposed outcome and finish line, strongest reason to start or wait, capacity displacement, missing evidence, and one next decision or shaping action.
