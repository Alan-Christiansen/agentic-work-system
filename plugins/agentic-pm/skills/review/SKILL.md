# Agentic PM: Review
Read [the shared operating policy](../../references/operating-policy.md) completely before acting.
## Select the review mode
Infer the narrowest useful scope from the request and current context, then read only the matching reference:
- For comparison across a domain, portfolio, or explicitly requested cross-domain capacity view, read [portfolio review](references/portfolio.md).
- For one Area or active, planned, blocked, or paused Project, read [record review](references/record.md).
- For an inactive item under an Area's Proposed Projects section, read [candidate review](references/candidate.md).
If the target is genuinely ambiguous and the choice would materially change the result, ask once. Do not make the user select an internal mode when the target is already clear.
## Shared boundaries
- A review request is read-only. Do not change tasks, urgency, lifecycle, priorities, classifications, goals, or `xPM/` state unless the user separately asks to reconcile accepted results.
- Preserve the Area, Project, and inactive-candidate distinctions. Candidate readiness never activates work; promotion requires explicit approval and the applicable project-creation workflow.
- Use only managed records for recommendations. Cross-domain prioritization requires an explicit request even when a generated dashboard shows every domain.
- Recommend one primary focus or maintenance action and at most one secondary responsibility when neglect would create a real cost.
## Deliver
Lead with the recommendation. Give the decisive evidence, displacement, blockers or missing evidence, unresolved state gaps, and one next decision or action. Identify proposed record changes separately from observations.
