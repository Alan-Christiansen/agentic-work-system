# Plan Week

Read [the shared operating policy](../../references/operating-policy.md) completely before acting.

## Plan

1. Establish the selected domain, the week's actual available work time, known hard stops, and material energy or attention constraints. Use a conservative stated assumption when only a minor detail is missing.
2. Load managed Areas and Projects in that domain using the policy's minimal context path. Respect current tasks, deadlines, blockers, dependencies, and accepted decisions.
3. Identify the one outcome that would make the week meaningfully successful. Add at most one secondary maintenance outcome when neglect would create a real cost.
4. Break the primary outcome into a small sequence of concrete moves sized to the available capacity. Keep later work visibly later.
5. Include recovery margin rather than filling every available hour. Flag any plan that depends on an unresolved approval, estimate, or external event.

Do not activate candidates, change priorities, or rewrite canonical tasks merely to make the plan look tidy. A planning request is read-only unless the user also asks to save or reconcile the plan.

## Deliver

State the primary weekly outcome, optional secondary maintenance outcome, first action, rough capacity allocation, displacement, and the condition that would trigger replanning.
